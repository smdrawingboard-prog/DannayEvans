Hireframe a Fate Collab product, built on Sealed

Recruitment software for small businesses — with signatures built in

Advertise the role, track the applicants, and get the offer signed. One system, one record, no attachments going back and forth.

This page is a static preview, not the running product.

GitHub Pages serves static files only. The platform is a Next.js app whose sign-in, pipelines, careers sites and the whole signing ceremony run on a server and read a live Postgres database — none of that can execute here. What follows is the product's public face, rendered with the real design system and the real prices read out of the live database, plus an honest account of what is built and what is not. The working application needs the deploy described in DEPLOYMENT.md.

One hire, start to signed

  1. Publish the role. The careers page is generated from the job record and carries schema.org JobPosting data, which is what Google Jobs and AI search actually read. Publishing is refused if the role has no summary, description or location — Google drops listings missing those, so a role published without them would silently never rank.
  2. Run the pipeline. Stages are configurable per business, because an eight-person agency and a 200-person employer do not share a hiring process. Cards turn amber past each stage's own target.
  3. Get it signed. Move a candidate to Offer and the pack goes out. Sealed records who viewed it, when, from which IP address, and how their identity was established, then issues a completion certificate.

Pricing

One envelope sent is one charge, however many people sign it. Charged on sending, not on signing.

Enterprise bulk bands

Counted from the first chargeable envelope, after the 750 included. Graduated, so crossing a threshold prices only the new envelopes — a bill can never jump backwards.

Why the ladder is shaped like that

Each tier's overage sits just above that tier's own effective included rate — R20.00 against R25.00, R11.99 against R14.00, R8.00 against R8.50. Going over is never punitive, but it is always slightly dearer than moving up, so the overage nudges an upgrade instead of breeding resentment. A customer who is consistently over is being told so by their own invoice. There is an assertion in the test suite that this property holds, so a future price change cannot quietly break it.

Regional prices are set to what each market bears. They are not conversions: R499 is not £29 at any exchange rate, and should not be. Excludes VAT and local sales tax.

What is built, and what is not

Working end to end
  • Multi-tenant schema with row-level security on all 45 tables
  • Sign-up, workspaces, memberships and roles
  • Sealed: create, send, sequential signing, decline, void, remind, audit trail, completion certificate
  • The signing ceremony, with access codes, explicit consent capture and IP evidence
  • Roles, candidates, pipeline board, business development, careers site editor, automations and settings
  • Public careers sites and job pages with JobPosting structured data
  • Public applications, creating the candidate, application and consent record
  • Per-envelope metering, entitlement checks and the in-app usage meter
Not done yet
  • No payment gateway. The meter, pricing engine and entitlement checks work; nothing charges a card and nothing raises an invoice at period close.
  • No sending. WhatsApp and email have schema, consent records and a queue, but no provider client — so the seven default automations are stored and toggleable but do not fire.
  • Assistants are not wired. All eleven are registered with their prompts and logging; the model call is not connected.
  • PDF flattening. Signatures are captured, evidenced and hashed, but not yet burned into the PDF itself.

How it is put together

Sealed is the product. Recruitment is the vertical.

The signature engine knows nothing about candidates. Everything the recruitment side needs goes through one interface with nine methods, so swapping the built-in engine for another signature application is one new class and one registry line. Each envelope records the provider that created it, so existing documents keep working after a switch.

Tenants are separated by the database, not the app

Every business table carries an organisation id, and access is granted only through a membership row. Row-level security is on for all 45 tables, so the database refuses cross-tenant access even if the application asks for it. Middleware is deliberately not the authorisation boundary — one route the matcher misses would be one unprotected route.

Evidence is the point

ECTA 2002 s13 in South Africa, the Electronic Communications Act 2000 in the UK and eIDAS in the EU all turn on the same thing: who signed, when, from where, and how their identity was established. The audit trail is append-only, enforced by a trigger and by revoking the privilege, so an attempt fails before the trigger even runs. The completion certificate carries a SHA-256 over the ordered event log plus every document hash.
